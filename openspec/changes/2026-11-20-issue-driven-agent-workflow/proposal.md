# Proposal

## Why

Исполнение задач сабагентами сейчас живёт только внутри сессии агента: план,
ход работ и результат не видны за пределами локального контекста, а момент
закрытия работы и публикации коммитов определяется вручную. Требуется связать
исполнение с GitHub Issues так, чтобы главный issue соответствовал change в
OpenSpec, каждый сабагент получал отдельный sub-issue с полным процессом от
начала до конца, а закрытие главного issue и пуш коммитов происходили только
после выполнения всех sub-issues и проверок. Без machine-проверяемого гейта
закрытие зависит от внимания исполнителя и легко происходит раньше времени.

## What Changes

- Добавить capability `issue-driven-workflow`, описывающую контракт главного
  issue, sub-issue сабагента, гейта готовности и авторизации публикации.
- Ввести machine-читаемые маркеры в телах issue: мета-маркер `issue-workflow:v1`
  и пары маркеров вокруг чеклистов критериев. Произвольный текст issue является
  данными и никогда не выполняется.
- Добавить CLI `scripts/issue_workflow/` с командами `init`, `status`, `sync`,
  `finish`: создание связанных issue из артефактов change, чтение статусов через
  GraphQL, синхронизация чеклиста, двухфазное закрытие с явным `--apply`.
- Добавить конвенцию в `AGENTS.md` и подробный протокол в
  `docs/issue-driven-workflow.md`, связывающий issue с карточкой
  `team-agent-orchestration` (owner, scope, acceptance, merge_gate, handoff).
- Добавить юнит-тесты на разбор маркеров, построение тел issue и таблицу
  истинности гейта.

### Out of Scope

- Изменение доменных инвариантов 1–12, бизнес-правил выдачи, владения,
  архивации, деактивации и просрочки.
- Изменение формата API, кодов ошибок, схемы БД, frontend и зависимостей.
- Замена OpenSpec: `openspec/specs/` остаётся источником правды; issue — только
  отражение хода исполнения.
- Автоматический пуш, auto-merge и GitHub Actions-триггеры. `--apply` требует
  явного подтверждения пользователя, merge в `main` — отдельное решение.
- Создание реальных issue на GitHub в рамках этого change: только фикстуры и
  `dry-run`.

## Capabilities

### New Capabilities

- `issue-driven-workflow`: контракт issue-ориентированного исполнения OpenSpec
  change через главный issue и sub-issues сабагентов.

### Modified Capabilities

Нет.

## Impact

- Новые файлы: `scripts/issue_workflow/**`, `docs/issue-driven-workflow.md`,
  `openspec/specs/issue-driven-workflow/spec.md`.
- Изменения: `AGENTS.md` (короткий раздел и ссылка), `.gitignore` (игнор `.tmp/`).
- Backend, frontend, зависимости и схема БД не затрагиваются.
