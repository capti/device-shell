# Design

## Context

FastAPI-приложение запускается одним процессом uvicorn. Сейчас есть только
`logger = logging.getLogger(__name__)` в `errors.py`; конфигурации логов нет,
поэтому записи идут в дефолтный обработчик uvicorn в текстовом виде, а доступа
к данным запроса (метод, путь, статус, длительность) в логах нет вообще.

## Goals / Non-Goals

**Goals:**

- Машиночитаемые строки лога без внешних зависимостей.
- Видно каждый HTTP-запрос и его статус, включая отказы и сбои.
- Уровень управляется настройкой, а не правкой кода.

**Non-Goals:**

- Сбор логов, ротация, запись в файл, трассировка, метрики.
- Изменение формата аудита в БД.

## Decisions

1. **Отдельный модуль `app/logs.py`, а не настройка в `main.py`.**
   Форматтер и настройка переиспользуются тестами и CLI, а `main.py` остаётся
   сборкой приложения. Имя модуля не `logging.py`, чтобы не путать с
   одноимённым модулем стандартной библиотеки.

2. **Свой `JsonFormatter`, а не сторонняя библиотека.** Нужны ровно четыре
   обязательных поля плюс `extra`; вводить зависимость ради этого нет смысла.
   Служебные атрибуты `LogRecord` перечислены в `_RESERVED`, остальные
   попадают в JSON — так появляются `method`, `path`, `status_code`,
   `duration_ms`.

3. **Переиспользование одного обработчика: `configure_logging` хранит ссылку
   на свой handler и снимает только его.** Полная очистка `root.handlers`
   сломала бы перехват логов в pytest (`caplog`) и любые обработчики,
   добавленные снаружи. Повторный вызов (например, второй `create_app` в
   тестах) не дублирует строки.

4. **Middleware запросов внешний по отношению к проверке Origin.** В Starlette
   последний добавленный middleware — самый внешний, поэтому
   `RequestLogMiddleware` добавляется после `OriginCheckMiddleware`: отказы
   403 тоже попадают в лог. Альтернатива — свой ASGI-middleware без
   `BaseHTTPMiddleware` — отклонена: в проекте уже используется
   `BaseHTTPMiddleware`, единообразие важнее микрооптимизации.

5. **В `extra` только безопасные поля.** Тело, cookie и заголовки не читаются
   вовсе, поэтому утечка пароля или токена сессии в лог невозможна по
   построению, а не за счёт фильтрации. Это закреплено тестом.

6. **Сбой запроса логируется уровнем ERROR через `logger.exception`** и
   пробрасывается дальше: ответ 500 формирует существующий обработчик ошибок,
   поведение API не меняется.
