# Design

## Context

Страница `/me` (`frontend/src/pages/profile/ProfilePage.tsx`) показывает два
блока устройств и внизу — инлайн-форму `ChangePasswordForm` с
`POST /auth/change-password`. На `/people` смена пароля другого сотрудника уже
сделана модальным окном (`PasswordModal` в `PeoplePage.tsx`) на Mantine
`Modal`. Backend не участвует в изменении.

## Goals / Non-Goals

**Goals:**

- Убрать инлайн-блок «Смена пароля» со страницы профиля.
- Дать тот же функционал через кнопку и модальное окно.
- Сохранить поведение формы: валидация, ошибки бэка, тост, очистка.

**Non-Goals:**

- Менять backend или контракт `POST /auth/change-password`.
- Переносить формы в общие компоненты (смена своего и чужого пароля —
  разные контракты: три поля против одного).
- Менять блоки устройств.

## Decisions

1. **Кнопка «Сменить пароль» в шапке страницы** рядом с заголовком
   «Мои устройства», по паттерну других страниц. Основная цель экрана —
   устройства, поэтому действие вынесено в правую часть заголовка.

2. **Mantine `Modal` (`centered`), как у `PasswordModal` на `/people`.**
   Единый визуальный язык для обоих окон смены пароля. Окно закрывается по
   крестику, Escape и кнопке «Отмена».

3. **Поведение не меняется.** `ChangePasswordForm` переезжает в
   `ChangePasswordModal` со всей валидацией (длина ≥ 8, совпадение
   подтверждения), текстом ошибки бэка и тостом. После успеха окно
   закрывается — состояния формы уничтожаются вместе с ним, поэтому очищать
   поля отдельно не нужно.

4. **Ошибки сервера не закрывают окно.** `INVALID_PASSWORD`/`WEAK_PASSWORD`
   показываются в модалке, ввод сохраняется: пользователь правит и повторяет,
   не переоткрывая форму.

5. **`MIN_PASSWORD_LENGTH` остаётся локальной константой страницы.** Общего
   компонента с `PeoplePage` не заводим: там одно поле без подтверждения,
   унификация усложнит оба случая вместо того, чтобы упростить.
