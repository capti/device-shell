# Proposal

## Why

Форма смены пароля на странице `/me` занимает постоянный блок внизу экрана,
хотя нужна эпизодически: пользователь открывает профиль, чтобы посмотреть свои
устройства, а не менять пароль. Инлайн-форма засоряет экран и разбавляет
основную цель страницы. В проекте уже принят модальный паттерн для
админского сброса пароля (`PasswordModal` на `/people`), и смена собственного
пароля должна выглядеть так же: кнопка в профиле → модальное окно.

## What Changes

- **Смена собственного пароля** переезжает из инлайн-блока «Смена пароля» в
  модальное окно: кнопка «Сменить пароль» в шапке страницы профиля открывает
  `Modal` с прежней формой (текущий пароль + новый + подтверждение).
- Поведение формы не меняется: валидация длины и совпадения, блокировка
  отправки, сохранение ввода при ошибке сервера, уведомление об успехе.
- После успешной смены модальное окно закрывается.

### Не входит

- Backend не меняется: `POST /auth/change-password` работает как раньше.
- Блоки «Владею» и «На руках сейчас» не трогаем.
- Смена пароля другого сотрудника через `/people` остаётся модаль�ным окном
  как есть.

## Capabilities

### Modified Capabilities

- `frontend-profile`: требование «Смена собственного пароля» — форма
  открывается в модальном окне, а не встроена в страницу.

## Impact

- Правки: `frontend/src/pages/profile/ProfilePage.tsx` (инлайн-форма →
  кнопка + `ChangePasswordModal`).
- Зависимости не нужны: Mantine `Modal` уже используется в `PeoplePage`.
