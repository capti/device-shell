# Design

## Структура

```
frontend/src/
  api/devices.ts        типы DeviceRead/DeviceList/DeviceEvent + запросы
  api/users.ts          GET /users (справочник для выбора владельца)
  pages/devices/
    DevicesListPage.tsx   таблица, фильтры, поиск, пагинация
    DeviceFormPage.tsx    создание и редактирование (общая форма)
    DeviceCardPage.tsx    карточка + таймлайн + архив/восстановление
  routes.tsx           /devices, /devices/new, /devices/:id, /devices/:id/edit
```

Типы повторяют `backend/app/schemas/devices.py`: `UserBrief`,
`DeviceRead` (включая вычисляемые `holder`, `overdue`, `expected_return_at`),
`DeviceListResponse`, `DeviceEventRead`. Запросы идут через существующий
`apiFetch`/`apiGet`/`apiPost` (`credentials: "include"`, конверт ошибок).

## Состояние списка — в URL

`useSearchParams`; параметры совпадают с именами бэка: `q`, `status`,
`overdue`, `mine`, `archived`, `sort`, `page`, `page_size`.
Пустые значения не пишем в URL — параметр просто отсутствует.

- Поиск: `TextInput` с debounce 300 мс → `setSearchParams` c `replace: true`,
  `page` сбрасывается в 1 при изменении любых фильтров.
- Чипы-переключатели (`Chip` из Mantine): «Мои» → `mine=true`,
  «Просроченные» → `overdue=true`, «В ремонте» → `status=repair`,
  «Архив» → `archived=true` (иначе `archived=false`).
- Сортировка: клик по заголовку инв. № / модели / обновления переключает
  прямой и обратный порядок (`inventory_no` ↔ `-inventory_no`).
- Пагинация: `Pagination` + `Select` 25/50/100; `page_size` меняется со
  сбросом на страницу 1.
- `useQuery` с `queryKey: ['devices', params]` — ключом служит сериализованная
  строка параметров, поэтому навигация по URL и «назад» работают без
  дополнительного кода.

Пустые состояния: нет ни одного устройства → «Устройств пока нет» + кнопка
«Добавить устройство»; есть, но поиск ничего не нашёл → «Ничего не найдено» +
«Сбросить фильтры» (H5).

## Форма устройства

`@mantine/form` (уже установлен), `useForm<DevicePayload>` с валидацией:
`brand` и `model` — непустые, `purchase_year` — целое в диапазоне бэка.
Кнопка «Сохранить» `disabled={!form.isDirty() || submitting}` плюс
`form.validate()` до отправки — пустые обязательные поля не дают сохранить (K4).

- `/devices/new`: поле владельца показывается только админу (Select активных
  пользователей, по умолчанию — текущий пользователь); обычному пользователю
  владелец = он сам и поле не отправляется (`owner_id` не передаём).
- `/devices/:id/edit`: значения из `GET /devices/{id}`; владелец и статус в
  форме не редактируются — это отдельные операции следующих этапов.
- Ответы `409` (дубликат инв. №/IMEI/serial) и `422` → тост с `message` из
  конверта, форма остаётся заполненной.

## Карточка

- Шапка: инв. № + модель, бейджи состояния: «В архиве», «Утерян»,
  «В ремонте», «Просрочен» (из `overdue`), иначе «Выдан»/«У владельца»
  по совпадению `holder.id == owner.id`.
- Две колонки: «Владелец» и «На руках у» (для архивного — то же, что владелец,
  плюс дата архивации), ожидаемый возврат `ДД.ММ.ГГГГ`.
- Характеристики — `Description`: ОС, память, цвет, тип, год, serial, IMEI,
  «Учётные записи», заметки; пустые поля не показываем.
- Таймлайн: `GET /devices/{id}/history`, событие → подпись на русском
  (`created` → «Создано», `updated` → «Изменено», `archived` → «Отправлено в
  архив», `restored` → «Восстановлено», `owner_changed` → «Сменён владелец»,
  остальные типы показываем как есть — они появятся на следующих этапах),
  актор, дата-время, `payload.changes` для `updated`.
- Доступность кнопок: `canManage = role === 'admin' || me.id === owner.id`;
  иначе «Редактировать» и «В архив» не рисуются.
- «В архив» — `Modal` с подтверждением (M2); `409 ACTIVE_CHECKOUT` → тост с
  текстом бэка, устройство не меняется. «Восстановить» — `Modal` с Select
  статуса (по умолчанию `active`); если бэк ответил `422 OWNER_REQUIRED`,
  в модалке появляется выбор нового владельца и повторная отправка.

## Ошибки

Везде тот же паттерн, что на дашборде: ловим `ApiError`, показываем
`notifications.show({ color: 'red', message })`; `ApiError.code === '401'`
обрабатывается общим обработчиком `api/client.ts` (редирект на `/login`).
Сетевые ошибки — «Ошибка сети. Повторите попытку».

## Верификация

- `npm run build` (tsc + vite) зелёный.
- Ручная сквозная проверка: backend (`uv run uvicorn` + тест-админ),
  `npm run dev` — создать 2–3 устройства, поиск/фильтры/пагинация, открытие
  по ссылке с фильтрами, редактирование, архив при активной выдаче (готовится
  через API вручную) → 409-сообщение, восстановление.
- `openspec validate --all --strict`; backend не меняется, `pytest`/`ruff`
  прогоняются как контроль, что ничего не откатилось.
