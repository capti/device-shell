# Spec Delta

## MODIFIED Requirements

### Requirement: Вход в систему

Сайт SHALL давать страницу `/login` для входа по имени пользователя и паролю
через `POST /auth/login`, а непопадание на защищённый маршрут SHALL вести
на её редиректом на `/login`.

#### Scenario: Вход с корректными данными

- **WHEN** сотрудник входит со своим username и паролем
- **THEN** сессия установлена httpOnly-cookie и целевой маршрут открывается с
  полной загрузкой документа; если исходный маршрут не задан, admin открывает
  `/dashboard`, а user — `/devices`

#### Scenario: Вход с неверными данными

- **WHEN** введён неверный username или пароль
- **THEN** под формой видна понятная ошибка на русском от конверта
  `UNAUTHORIZED` бэка

#### Scenario: Неавторизованный на защищённом маршруте

- **WHEN** пользователь без сессии открывает `/dashboard`
- **THEN** его перенаправляет на `/login`, а после входа возвращают туда,
  куда он шёл

#### Scenario: Выход

- **WHEN** сотрудник нажимает «Выйти»
- **THEN** вызывается `POST /auth/logout`, сессия сброшена и открыт `/login`

### Requirement: Оболочка и навигация

Приложение SHALL иметь постоянную оболочку (шапка + боковая навигация) со
ссылками: Устройства `/devices`, Люди `/people`, Отчёты `/reports`, а для
роли admin дополнительно — Дашборд `/dashboard`. Реализованные разделы
SHALL показывать данные, нереализованные — заглушку «Раздел в разработке».

#### Scenario: Переход между разделами

- **WHEN** пользователь открывает пункт навигации
- **THEN** URL меняется на его маршрут, активный пункт визуально отмечен,
  содержимое отрисуется без перезагрузки страницы

#### Scenario: Реализованный раздел устройств

- **WHEN** пользователь открывает `/devices`
- **THEN** виден рабочий список устройств, а не заглушка

#### Scenario: Нереализованный раздел

- **WHEN** пользователь открывает `/people` или `/reports`
- **THEN** виден экран заглушки, а ошибка не возникает

#### Scenario: Навигация админа

- **WHEN** пользователь с ролью admin видит боковую навигацию
- **THEN** видны пункты «Дашборд», «Устройства», «Люди» и «Отчёты»

#### Scenario: Пункт «Дашборд» скрыт от обычного пользователя

- **WHEN** пользователь с ролью user видит боковую навигацию
- **THEN** пункта «Дашборд» нет, а остальные пункты на месте

### Requirement: Дашборд со счётчиками и просрочками

`/dashboard` SHALL показывать все семь счётчиков из `GET /dashboard/stats`
и блок «Просроченные» — до пяти давних просрочек с инвентарным номером,
моделью, держателем и числом дней просрочки. Страница SHALL быть доступна
только роли admin; пользователь с ролью user, открывший `/dashboard`,
SHALL быть перенаправлен на `/devices`.

#### Scenario: Открытие дашборда

- **WHEN** admin открывает `/dashboard`
- **THEN** видны семь счётчиков и топ просрочек, отсортированный по
  давности, как их отдал backend

#### Scenario: Нет просроченных

- **WHEN** просроченных выдач нет
- **THEN** блок показывает состояние «Нет просроченных возвратов»,
  счётчик `overdue` = 0

#### Scenario: Обычный пользователь открывает дашборд по URL

- **WHEN** пользователь с ролью user открывает `/dashboard` напрямую
- **THEN** его перенаправляет на `/devices`, а данные дашборда не запрашиваются

### Requirement: Графики на дашборде

`/dashboard` SHALL показывать три графика: «Выдачи и возвраты» (bar по месяцам
за 12 месяцев из `GET /dashboard/charts`), «Состояние парка» (donut из
счётчиков `GET /dashboard/stats`) и «Возраст просрочки» (bar по корзинам
1–7 / 8–14 / 15–30 / 31+ дней). Ошибка загрузки графиков SHALL не блокировать
счётчики и таблицу просрочек.

#### Scenario: Открытие дашборда

- **WHEN** admin открывает `/dashboard` и оба запроса успешны
- **THEN** видны три графика: динамика выдач и возвратов за 12 месяцев с
  подписями месяцев, donut с состоянием парка и корзины возраста просрочки

#### Scenario: Ошибка агрегатов графиков

- **WHEN** `GET /dashboard/charts` завершается ошибкой
- **THEN** блок графиков показывает сообщение об ошибке, а счётчики, donut и
  таблица просрочек отображаются как обычно

#### Scenario: Нет данных для графика

- **WHEN** за период не было ни выдач, ни возвратов
- **THEN** график динамики показывает пустое состояние, а не пустой прямоугольник
