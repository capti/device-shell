# Design

## Context

Backend уже предоставляет `GET /health`: ответ отражает доступность приложения и БД. В разработке backend запускается локально на порту 8000; проект не использует Docker.

## Goals / Non-Goals

- Запускать мониторинг отдельным процессом на Windows без изменения backend.
- Ограничить веб-интерфейс Gatus loopback-интерфейсом.
- Сохранять историю проверок между перезапусками.
- Не устанавливать Gatus автоматически и не добавлять его в зависимости приложения.

## Decisions

### Запуск официального бинарника, установленного Go

Использовать официальную команду `go install github.com/TwiN/gatus/v5@latest`; скрипт проекта находит команду `gatus` в `PATH`. Это не требует Docker и не добавляет скомпилированный бинарник в репозиторий. Альтернатива — Docker Compose — потребовала бы отдельной контейнерной конфигурации и сетевого доступа контейнера к backend.

### Проверка существующего health endpoint

Gatus опрашивает `http://127.0.0.1:8000/health` раз в минуту. Проверяются HTTP 200 и оба JSON-признака `status: ok`, `database: ok`. Отдельный endpoint не создаётся: существующий health-check уже отражает доступность БД.

### Локальная панель и SQLite-хранилище

Gatus слушает `127.0.0.1:8081`, чтобы панель статуса не была доступна из локальной сети. История сохраняется в `data/gatus.db`, внутри уже игнорируемого каталогом Git хранилища данных проекта.

## Risks / Trade-offs

- [Backend не запущен или использует другой порт] → проверка будет красной; README указывает запуск backend на `:8000` как предварительное условие.
- [Go или Gatus не установлены / Gatus не находится в `PATH`] → скрипт завершится с понятной инструкцией по установке.
- [Панель не видна с других компьютеров] → это намеренно для локального режима; публикация панели требует отдельного решения по доступу и защите.

## Migration Plan

1. Установить Go, затем Gatus официальной командой `go install`.
2. Запустить backend, затем `.\start-gatus.ps1`.
3. Открыть `http://localhost:8081`; проверить статус API.

Для отката остановить Gatus и удалить конфигурацию/скрипт мониторинга. Данные приложения не меняются; историю можно удалить отдельно вместе с `data/gatus.db`.
