# Spec Delta

## Purpose

Дополняет `audit-log`: журнал входов фиксируется в БД и доступен админу.

## MODIFIED Requirements

### Requirement: Журнал входов

Система SHALL фиксировать каждую попытку входа — успешную и неуспешную — со
временем, введённым логином, исходом, причиной отказа, IP-адресом и
user-agent. Записи журнала SHALL быть неизменяемыми на уровне базы данных.

Admin SHALL видеть журнал через `GET /audit/logins` с фильтрами по дате,
логину и исходу. Количество записей в ответе SHALL ограничиваться, чтобы поток
неудачных попыток не раздувал ответ.

#### Scenario: Неуспешный вход

- **WHEN** пользователь вводит неверный пароль
- **THEN** в журнале появляется запись с исходом «неуспешно» и причиной
  «неверные учётные данные»

#### Scenario: Успешный вход

- **WHEN** пользователь входит с верным паролем
- **THEN** в журнале появляется запись с исходом «успешно» и ссылкой на
  пользователя

#### Scenario: Попытка с неизвестным логином

- **WHEN** вход пытаются выполнить под логином, которого нет
- **THEN** в журнале появляется запись с введённым логином и без ссылки на
  пользователя

#### Scenario: Попытка под деактивированной учётной записью

- **WHEN** вход пытаются выполнить под деактивированной учётной записью
- **THEN** в журнале появляется неуспешная запись с причиной
  «деактивированная учётная запись»

#### Scenario: Попытка, отсечённая rate-limit'ом

- **WHEN** вход отклонён ограничителем попыток
- **THEN** в журнале появляется неуспешная запись с причиной «rate limit»
  и введённым логином

#### Scenario: Отказ базы данных не прячет попытку

- **WHEN** вход отклонён с кодом 401 или 429
- **THEN** запись журнала сохраняется, несмотря на откат транзакции запроса

#### Scenario: Запись нельзя изменить или удалить

- **WHEN** кто-либо пытается изменить или удалить запись журнала
- **THEN** база данных отклоняет операцию

#### Scenario: Фильтры и ограничение ответа

- **WHEN** admin запрашивает журнал с фильтрами по дате, логину и исходу
- **THEN** ответ содержит только подходящие записи, не больше заданного
  лимита, и общее число подходящих записей

#### Scenario: Журнал входов только для администратора

- **WHEN** пользователь с ролью `user` запрашивает журнал входов
- **THEN** система отвечает 403 `FORBIDDEN` и не возвращает записи
