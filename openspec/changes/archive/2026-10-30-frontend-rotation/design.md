## Контекст

Бэкенд оборота готов: `POST /devices/{id}/checkout` принимает `holder_id`,
`expected_return_at`, `condition_out`, `comment_out`; `POST /devices/{id}/transfer`
— `holder_id`, `expected_return_at`, `condition_in`, `comment`. Оба возвращают
карточку устройства. Инварианты (нельзя выдать самому себе, максимум одна
активная выдача) держит сервис, фронт их не дублирует — только не показывает
заведомо невалидные варианты.

## Решения

**Срок возврата — нативный `<input type="date">` через `TextInput type="date"`.**
`@mantine/dates` в проекте не подключён, а ради одного поля тянуть пакет с
dayjs-зависимостью не стоит. Значение `YYYY-MM-DD` превращается в ISO
`YYYY-MM-DDT00:00:00` — бэк ждёт `datetime`.

**Один компонент `RotationDialogs` на два диалога.** Формы отличаются только
подписью кнопки, полем состояния (`condition_out` против `condition_in`) и
эндпоинтом, поэтому общий `RotationModal` с параметром `mode` держит обе.

**Список сотрудников — `fetchUsers()` без неактивных.** Деактивированных в
выдачу не отдаём: бэк всё равно откажет, но диалог не должен их предлагать.

**Пустые поля не отправляются.** `expected_return_at` и комментарий собираются в
payload условно (`...(value ? { key: value } : {})`), `condition_out` — только
при выбранном значении: `extra="forbid"` на бэке не терпит лишнего, а
`null` в комментарии неотличим от отсутствия.

**Права считаются на карточке и передаются вниз.** `canCheckout` = не архив, не
выдано, пользователь — admin или владелец. `canTransfer` = не архив, выдано,
пользователь — admin, владелец или текущий держатель. Это те же условия, что и
в сервисе; расхождение даст 403 с понятным сообщением, а не тихую поломку.

**Ошибка показывается внутри диалога, успех — тостом.** 409/403 нужно прочитать
и, возможно, исправить ввод, поэтому текст ошибки живёт в модалке; успешное
действие закрывает диалог, показывает тост и обновляет карточку.

## Альтернативы

- Отдельные страницы «Выдать»/«Передать» — лишняя навигация для двух полей.
- Переиспользовать `CheckoutCreate` как форму редактирования выдачи — выдача не
  редактируется, только создаётся и закрывается.
- Показ списка `GET /devices/{id}/checkouts` — истории выдач достаточно в
  таймлайне событий карточки; отдельная таблица не нужна для этой задачи.

## Риски

- Даты: бэк сравнивает `expected_return_at` с датой дня для просрочки; фронт
  отправляет полночь выбранного дня, что совпадает с ожиданием бэка.
- Часовой пояс: `YYYY-MM-DDT00:00:00` без зоны трактуется бэком как локальная
  дата — тот же формат уже используется в фильтрах списка.
