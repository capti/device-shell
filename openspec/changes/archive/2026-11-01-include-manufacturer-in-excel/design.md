# Design

## Context

Excel формируется в backend-сервисе отчётов. Производитель (`brand`) уже
сохранён в модели устройства; отдельный API-запрос или миграция не нужны.
Текущие листы «Все устройства», «Просроченные» и «История выдач» уже выводят
модель, но не производителя.

## Goals / Non-Goals

**Goals:**
- Сохранить соответствие между устройством, производителем и моделью на всех
  листах выгрузки.
- Проверить заголовки и значения столбцов через скачанный XLSX-файл.

**Non-Goals:**
- Изменять API отчётов, БД, фильтрацию или форматирование остальных полей.

## Decisions

- Добавлять `brand` непосредственно перед `model` во все три схемы листов.
  Единый порядок позволяет одинаково идентифицировать устройство в каждой
  выгрузке; добавление только на один лист оставило бы остальные неполными.
- Проверять результат на уровне API-экспорта с чтением XLSX, а не только
  внутренние структуры построения книги.

## Risks / Trade-offs

- Добавление столбца сдвигает индексы последующих ячеек → обновить существующие
  тесты, которые проверяют значения по позициям.

## Migration Plan

Изменение не требует миграции данных или отдельного шага развёртывания.
При откате достаточно вернуть прежние заголовки и строки генерации XLSX.
