# Design

## Context

Вход выполняется API-вызовом из SPA, после которого React Router переходит
на защищённый маршрут. Полная навигация при редиректе по 401 уже применяется
в `main.tsx`. Целевой путь после входа — внутренний pathname, сохранённый
защитным маршрутом, либо `/dashboard`.

## Goals / Non-Goals

**Goals:**
- Использовать браузерную навигацию документа после успешного входа.
- Ограничить редирект внутренними абсолютными путями приложения.

**Non-Goals:**
- Скрывать отправленный пароль из DevTools или менять способ аутентификации.
- Менять серверный API, сессии, cookie, неуспешный вход или навигацию между
  разделами приложения.

## Decisions

- После успешного API-ответа использовать полную навигацию с заменой текущей
  записи истории, сохраняя существующую семантику `replace`.
- Перед навигацией принимать сохранённый pathname только если он начинается
  с одного `/` и не начинается с `//`; иначе использовать `/dashboard`.
  Это не допускает перехода на внешний origin из состояния маршрута.
- Не сохранять успех входа или credentials в persistent storage. Сообщение
  об успешном входе заменяется непосредственным открытием защищённой страницы.

## Risks / Trade-offs

- DevTools может сохранять запрос после перехода, если включён Preserve log,
  и всегда показывает активный запрос до завершения → не представлять
  перезагрузку как защиту пароля.
- Полная загрузка заново запрашивает профиль и данные страницы → сессия уже
  установлена сервером до получения успешного ответа входа.

## Migration Plan

Миграции БД и API не требуются. Откат — вернуть клиентскую навигацию React
Router после успешного входа.
