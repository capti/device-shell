# Proposal

## Why

Сайт через dev-сервер Vite (:5173) не может войти в систему: POST
`http://localhost:5173/auth/login` отвечает 404 «Запрос не найден».

Причина — расхождение между прокси и API-клиентом с первого коммита фронтенда
(`e7e025d`): `vite.config.ts` настроен проксировать только префикс `/api`
(с последующим strip'ом), а `src/api/client.ts` вызывает голые пути
(`/auth/login`, `/devices`, …) без префикса. В dev-режиме каждый запрос API
попадает в статику Vite, а не на :8000.

Раньше это не всплыло, потому что сквозная проверка прошлых изменений шла
напрямую к backend (`Invoke-RestMethod http://localhost:8000/...`), мимо
браузера и прокси. В браузере через :5173 не работает ничего, что ходит в API.

## What Changes

- **`src/api/client.ts`** — единая база запросов: в dev-режиме все вызовы API
  идут под префиксом `/api` (его прокси снимает перед отправкой на :8000),
  в production-сборке — как сейчас, без префикса. Решение живёт в одном месте
  (`API_BASE` + хелпер `apiUrl`), модули `src/api/*` не меняются.
- **`src/api/reports.ts`** — `exportUrl()` строит ссылку на Excel-файл через
  тот же хелпер, чтобы кнопка выгрузки работала в dev.
- **`vite.config.ts`** — прокси также пропускает `/media/*` (фотоустройства):
  backend возвращает относительные URL вида `/media/devices/1/...`, которые в
  dev иначе отдаёт Vite с 404.

### Не входит

- Статическая раздача `frontend/dist` через FastAPI (однопортовый прод) —
  отдельный change, как было зафиксировано в `frontend-bootstrap`.
- Монтирование backend-роутов под `/api` — контракт API остаётся голыми
  путями (`POST /auth/login` и т.д., спеки `frontend-shell`, `api-schema`).
- Тестовая инфраструктура фронтенда (Vitest/Playwright) — отложена.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет — поведение, требуемое спекой `frontend-shell` («вход через
`POST /auth/login`»), не меняется; код приводится в соответствие со спекой.
Изменение — dev-обвязка, а не изменение поведения системы.

## Impact

- `frontend/src/api/client.ts`, `frontend/src/api/reports.ts`,
  `frontend/vite.config.ts`.
- Backend не затрагивается; OpenAPI и спеки не меняются.
- `SETUP.md`/`README.md` не требуют правок: они уже описывают прокси `/api`
  → `:8000` как задуманный режим — после изменения он становится фактическим.
