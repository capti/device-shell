# Design

## Context

`backend/openapi.json` пишется командой `python -m app.export_openapi` и
коммитится. Единственные проверки файла — тесты пути в `test_openapi.py`,
которые строят схему в `tmp_path` и с закоммиченным файлом не сверяются.

## Decisions

1. **Guard сравнивает структуру, а не байты.** Тест читает закоммиченный файл и
   сравнивает его с `app.openapi()` через `json.loads` + `==`: сравнение
   словарей не зависит от порядка ключей и форматирования, поэтому случайный
   reformat не сломает CI.

2. **Файл сверяется с `create_app()`, а не с модульным `app`.** Модульный
   `app` создаётся при импорте и уже содержит все роутеры; `create_app()`
   гарантированно строит чистое приложение — тем же способом, каким пишет
   `export_openapi`.

3. **Одно направление проверки.** Guard не перегенерирует файл сам: авто-запись
   в тестах замыла бы реальное расхождение и оставила бы его незамеченным в
   репозитории. Падение с подсказкой команды — дешевле и заметнее.

4. **Кириллица остаётся сырой.** `export_openapi` пишет `ensure_ascii=False`;
   отдельный существующий тест проверяет отсутствие `\u04` в тексте. Guard
   сравнивает структуру, поэтому на кодировку не влияет.

5. **Ответ `/health` документируется через `responses`, а не через
   `response_model`.** Эндпоинт обязан отдавать `JSONResponse` напрямую —
   иначе глобальный обработчик ошибок снова сотрёт payload в конверт
   `{code, message}`. Сочетание `response_model=None` + `responses={200, 503}`
   с моделью `HealthStatus` (`status` и `database` — `Literal`) описывает оба
   исхода в OpenAPI, не вмешиваясь в рантайм. Модель только документирует:
   валидация ответа через неё не проходит.

## Risks / Trade-offs

- Guard требует дисциплины «перегенерировал — закоммитил»: без этого коммит
  с новым эндпоинтом уйдёт с красным тестом. Это и есть цель — расхождение
  видно до слияния, а не при сборке фронтенда.

## Alternatives Considered

- **Сверка по строкам файла** — отклонена: любое изменение форматирования
  json.dumps дало бы ложное срабатывание.
- **Генерация схемы на этапе сборки фронтенда** — отклонена: фронтенд
  собирается отдельно и не должен поднимать backend ради типов.
