# Proposal

## Why

B10 требовал сохранять OpenAPI-схему в `backend/openapi.json` — фронтенд
генерирует из неё типы. Файл закоммичен, но ничего не гарантирует его свежесть:
тесты `test_openapi.py` экспортируют схему во временный каталог и проверяют
только наличие путей, поэтому расхождение с кодом не видно.

Расхождение уже случилось: после добавления `GET /audit/events` и изменения
`/health` (появились `database` и `degraded`) закоммиченный файл остался
старым. Тесты зелёные, фронтенд получает устаревшую схему.

## What Changes

- **Требование о свежести схемы**: закоммиченный `backend/openapi.json` SHALL
  совпадать с тем, что отдаёт `app.openapi()`. Новое capability `api-schema`.
- **Guard-тест**: `pytest` падает, если файл отстал от кода, с подсказкой
  перегенерации.
- **Перегенерация**: `openapi.json` приводится в соответствие с текущим кодом
  (`/audit/events`, обновлённый `/health`).
- **Документация ответа `/health`**: эндпоинт отдаёт ответ напрямую через
  `JSONResponse` (`response_model=None`), и схема ответа опустела до `{}` —
  поля `database` и `degraded` перестали быть описанными. Возвращаем
  описание через модель `HealthStatus` и `responses` в декораторе, поведение
  эндпоинта не меняется.

### Не входит

- Автоперегенерация схемы при сборке: остаётся явная команда
  `python -m app.export_openapi`, guard только ловит расхождение.
- Генерация типов фронтенда из схемы — отдельный шаг на фронте.

## Capabilities

### New Capabilities

- `api-schema`: требование синхронности закоммиченной OpenAPI-схемы с кодом.

### Modified Capabilities

Нет: поведение API не меняется, схема становится актуальной, а не новой.

## Impact

- Новые: `openspec/specs/api-schema/spec.md` (после архивации).
- Правки: `backend/openapi.json` (перегенерация),
  `backend/tests/test_openapi.py` (guard-тест).
- Зависимостей нет: используется существующий `app.export_openapi`.
