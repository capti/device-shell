# Proposal

## Why

Фото и отчёты о состоянии лежат в `data/media/`, а вся учётная информация — в
`data/qa.db` (SQLite в режиме WAL). Копирования только файла базы недостаточно:
в WAL часть данных ещё не перенесена в основной файл, а без `media/` теряется
история состояния устройств. Риски R1, R2 и R5 из PLAN.md требуют бэкапа перед
обновлением, инструкции по восстановлению и регулярной проверки восстановления.

## What Changes

- **Команда бэкапа**: `python -m app.cli backup` создаёт каталог
  `data/backups/qa-backup-<ГГГГ-ММ-ДД>_<ЧЧ-ММ-СС>/` с копией базы и всего
  `data/media/`. Копия базы снимается средствами SQLite (backup API), а не
  копированием файла, поэтому WAL не делает её битой.
- **Ретенция**: после создания хранятся 14 последних копий (G3), более старые
  удаляются; `--keep N` меняет лимит.
- **Восстановление**: `python -m app.cli restore <каталог>` возвращает базу и
  media из копии; требует подтверждения, если не указан `--yes`.
- **Запуск по расписанию**: обёртка `backup.ps1` в корне репозитория для
  Планировщика Windows, инструкция — в README.
- **Ошибки**: отсутствующий файл базы, копия без базы, повторная копия в ту же
  секунду и некорректный лимит дают понятный `{code, message}` в CLI.

### Не входит

- Изменение поведения API и схемы БД: миграций нет, эндпоинтов не добавляется.
- Шифрование, выгрузка копий в облако и на внешние диски: копии локальные, в
  `data/backups/`.
- Автоматическая проверка копий по расписанию (R5 остаётся ручной процедурой).
- Очистка `data/backups/` от не-`qa-backup-*` каталогов: скрипт трогает только
  свои копии.
- Аудит-журнал, структурные логи и `/health` из общего шага B9: они уже
  реализованы, здесь меняется только хранение данных.

## Capabilities

### New Capabilities

- `data-backup`: резервное копирование и восстановление `data/` — каталог копии,
  согласованность SQLite с WAL, ретенция 14 копий, восстановление и запуск по
  расписанию.

### Modified Capabilities

Нет: поведение API и существующих capability-спек не меняется.

## Impact

- Новые: `backend/app/services/backup.py`, `backend/tests/test_backup.py`,
  `backup.ps1`.
- Правки: `backend/app/config.py` (свойство `backup_dir`),
  `backend/app/cli.py` (команды `backup` и `restore`),
  `backend/tests/conftest.py` (каталог копий во временный для тестов),
  `README.md` (раздел «Бэкап и восстановление»).
- Новых зависимостей нет: используется стандартный `sqlite3` и `shutil`.
