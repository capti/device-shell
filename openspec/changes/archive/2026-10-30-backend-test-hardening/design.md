# Design

## Context

Все инварианты уже имеют тесты: модели (`test_models_*.py`), API-сценарии
(`test_checkouts.py`, `test_devices_archive.py`, `test_users_deactivate.py` и
др.) и общая функция просрочки (`test_device_state.py`). Чего не хватает, так
это явной связи «инвариант → тест» и защиты схемы OpenAPI для отчётных
эндпоинтов, которые появились после первых тестов схемы.

## Decisions

1. **Не дублировать тесты ради матрицы.** Инвариант считается покрытым, если
   существующий тест падает при его нарушении; проверено чтением тестов, а не
   копированием сценариев в новый файл. Дубли ухудшили бы `dryer` и время
   прогона.

2. **Матрица живёт в README, а не в тесте.** Тест, проверяющий наличие строк в
   markdown, хрупок и ничего не доказывает; README — то место, куда смотрит
   человек при ревью. Формат: таблица «инвариант → файл теста».

3. **Отчётные эндпоинты проверяются по выгруженной схеме**, как остальные
   наборы в `test_openapi.py`: тест вызывает `export_openapi()` во временный
   каталог и ищет пути в JSON. Так проверяется именно артефакт, который
   используется для генерации типов фронтенда.

4. **`openapi.json` перегенерируется, а не правится руками.** Расхождение
   видно по `git diff`: если файл изменился без изменения роутов — это признак
   устаревшей выгрузки.

## Non-Goals

- Новые проверки поведения и правки сервисов.
- Изменение структуры тестовых фикстур.
