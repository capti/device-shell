# Spec Delta

## Purpose

Управляет справочником сотрудников и корректно завершает их участие, не теряя
историю.

## ADDED Requirements

### Requirement: Создание пользователей

Создавать учётные записи SHALL только admin; саморегистрация MUST быть
недоступна.

#### Scenario: Админ создаёт сотрудника
- **WHEN** admin заполняет username, ФИО, пароль и роль
- **THEN** система создаёт активную учётную запись

#### Scenario: Саморегистрация
- **WHEN** неаутентифицированный пользователь пытается создать учётную запись
- **THEN** система отвечает 401

### Requirement: Обязательные поля пользователя

Учётная запись SHALL требовать username, ФИО и пароль при создании; username
должен быть уникальным.

#### Scenario: Дубликат username
- **WHEN** admin создаёт пользователя с занятым username
- **THEN** система отвечает 409

### Requirement: Дополнительные поля пользователя

Карточка сотрудника SHALL хранить email, команду и Telegram, если они указаны.

#### Scenario: Профиль с контактами
- **WHEN** пользователь открывает карточку сотрудника
- **THEN** он видит заполненные контактные поля

### Requirement: Деактивация пользователя

Деактивация SHALL переводить все устройства пользователя в архив.

#### Scenario: Деактивация владельца устройств
- **WHEN** admin деактивирует пользователя без активных выдач
- **THEN** все его устройства архивируются, доступ к системе закрывается

### Requirement: Блокировка деактивации при обороте

Деактивация MUST отклоняться, если у пользователя на руках чужие устройства или
у его устройств есть активные выдачи.

#### Scenario: Деактивация держателя
- **WHEN** admin пытается деактивировать пользователя, у которого на руках чужой телефон
- **THEN** система отвечает 409 и возвращает список проблемных устройств

### Requirement: Восстановление пользователя

Восстановление SHALL возвращать доступ к системе, но MUST NOT возвращать
устройства из архива автоматически.

#### Scenario: Возврат сотрудника
- **WHEN** admin активирует ранее деактивированного пользователя
- **THEN** пользователь снова может войти, его устройства остаются в архиве

### Requirement: Скрытие деактивированных из выбора

Деактивированные пользователи MUST NOT предлагаться как владелец или держатель.

#### Scenario: Выбор владельца
- **WHEN** пользователь выбирает владельца устройства
- **THEN** в списке только активные сотрудники

### Requirement: Запрет удаления пользователя

Система MUST NOT удалять учётные записи; доступна только деактивация.

#### Scenario: Попытка удаления
- **WHEN** admin пытается удалить пользователя
- **THEN** система отвечает 405 и предлагает деактивацию

### Requirement: Список сотрудников

Список SHALL показывать количество устройств во владении и на руках у каждого
сотрудника.

#### Scenario: Сводка по сотруднику
- **WHEN** admin открывает список сотрудников
- **THEN** напротив каждого видны счётчики «владеет» и «на руках»
