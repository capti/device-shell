# Design

## Context

Спека `audit-log` после архивации `backend-review-hardening` содержит описание
требования «Глобальный журнал» длиной 578 символов. Порядок при равном времени
уже описан в сценарии «События с равным временем», поэтому дублирующая фраза в
описании не несёт новой информации.

## Goals / Non-Goals

**Goals:**

- Сократить описание требования до корректной длины без потери требований.
- Восстановить прохождение строгой валидации OpenSpec.

**Non-Goals:**

- Менять поведение, сценарии, коды ошибок и формат ответов.
- Менять код, тесты, БД и другие спеки.

## Decisions

- Удаляется только фраза «При равном времени создания порядок SHALL
  определяться убыванием `id`» из описания. Сценарий «События с равным временем»
  остаётся единственным и полным выражением этого требования: он задаёт и
  порядок, и стабильность между запросами.
- Все остальные абзацы и сценарии переносятся без изменений (MODIFIED требует
  полного блока требования).

## Risks / Trade-offs

- [Читающий описание requirement может не заметить правило порядка] → правило
  остаётся в сценарии, который является частью того же требования и проверяется
  тестом `test_audit_events_with_equal_timestamps_order_by_descending_id`.

## Migration Plan

Миграция БД и кода не требуется. После архивации change синхронизирует
исправленную спеку; откат — архивация change с обратной формулировкой.
