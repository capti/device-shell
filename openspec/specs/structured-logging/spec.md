# structured-logging Specification

## Purpose
Пишет логи приложения в машиночитаемом виде: одна JSON-строка на событие, с
полями запроса и трейсбеком сбоя, без секретов.

## Requirements

### Requirement: Формат записи

Система SHALL выводить каждое сообщение лога одной JSON-строкой, содержащей
`timestamp` в UTC, `level`, `logger`, `message` и все поля, переданные через
`extra`.

#### Scenario: Обычная запись

- **WHEN** приложение пишет лог уровня INFO с дополнительным полем
- **THEN** в выводе появляется одна строка, которая разбирается как JSON и
  содержит `timestamp`, `level`, `logger`, `message` и это поле

#### Scenario: Сбой с трейсбеком

- **WHEN** запись логируется с информацией об исключении
- **THEN** JSON содержит поле `exception` с текстом трейсбека

### Requirement: Уровень логирования

Система SHALL брать уровень из настройки `LOG_LEVEL` и SHALL не дублировать
вывод при повторной настройке логов.

#### Scenario: Уровень из настроек

- **WHEN** уровень задан как `WARNING`
- **THEN** записи INFO не выводятся, а WARNING выводятся

#### Scenario: Повторная настройка

- **WHEN** логи настраиваются дважды за процесс
- **THEN** каждое сообщение выводится один раз

### Requirement: Логирование HTTP-запросов

Система SHALL писать строку на каждый обработанный запрос с полями `method`,
`path`, `status_code` и `duration_ms`.

#### Scenario: Успешный запрос

- **WHEN** выполняется запрос, вернувший 200
- **THEN** в логе есть запись с этим путём, статусом и неотрицательной
  длительностью

#### Scenario: Отказ проверки Origin

- **WHEN** мутация отклонена проверкой Origin с кодом 403
- **THEN** запрос всё равно попадает в лог со статусом 403

#### Scenario: Необработанное исключение

- **WHEN** обработчик запроса падает с исключением
- **THEN** появляется запись уровня ERROR с трейсбеком и статусом 500, а клиент
  получает прежний ответ 500

### Requirement: Секреты не попадают в лог

Запись о запросе SHALL содержать только метод, путь, статус и длительность;
тело запроса, cookie и заголовок авторизации SHALL не логироваться.

#### Scenario: Пароль в теле запроса

- **WHEN** выполняется вход с паролем в теле запроса
- **THEN** в логах нет ни пароля, ни заголовка авторизации
