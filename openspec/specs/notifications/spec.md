# notifications Specification

## Purpose
Доставляет адресные уведомления о значимых событиях внутри приложения.

## Requirements

### Requirement: Уведомление о смене владельца

Если владельца устройства меняет не admin, система SHALL уведомить всех
активных администраторов.

#### Scenario: Смена владельца обычным пользователем
- **WHEN** user передаёт владение своим устройством
- **THEN** каждый активный admin получает уведомление

### Requirement: Уведомление об архивации и восстановлении

Если устройство архивирует или восстанавливает не admin, система SHALL
уведомить всех активных администраторов.

#### Scenario: Пользователь архивирует устройство
- **WHEN** user отправляет своё устройство в архив
- **THEN** администраторы получают уведомление

### Requirement: Уведомление об утере и запросе ремонта

Система SHALL уведомлять администраторов, когда устройство помечено как
утерянное или в отчёте выставлен флаг «требует ремонта».

#### Scenario: Отметка об утере
- **WHEN** владелец переводит устройство в статус `lost`
- **THEN** администраторы получают уведомление

### Requirement: Уведомление владельцу о выдаче

Система SHALL уведомлять владельца, когда его устройство выдано другому
сотруднику.

#### Scenario: Выдача чужого устройства
- **WHEN** устройство выдано коллеге
- **THEN** владелец получает уведомление о выдаче

### Requirement: Уведомление владельцу о возврате

Система SHALL уведомлять владельца, когда его устройство возвращено.

#### Scenario: Возврат устройства
- **WHEN** держатель возвращает устройство
- **THEN** владелец получает уведомление о возврате

### Requirement: Уведомление о просрочке

При наступлении просрочки система SHALL однократно уведомить владельца и всех
администраторов.

#### Scenario: Просрочка наступила
- **WHEN** наступает день после ожидаемой даты возврата, а устройство не вернули
- **THEN** владелец и администраторы получают по одному уведомлению

#### Scenario: Повторное уведомление
- **WHEN** просрочка продолжается на следующий день
- **THEN** повторное уведомление не отправляется

### Requirement: Отметка «прочитано»

Пользователь SHALL отмечать уведомления прочитанными по одному или все сразу.

#### Scenario: Прочитать все
- **WHEN** пользователь нажимает «Прочитать всё»
- **THEN** все его уведомления получают отметку о прочтении

### Requirement: Счётчик непрочитанных

Система SHALL показывать количество непрочитанных уведомлений.

#### Scenario: Новое уведомление
- **WHEN** пользователь получает уведомление
- **THEN** счётчик увеличивается на единицу

### Requirement: Срок хранения уведомлений

Уведомления SHALL храниться 90 дней, после чего удаляться автоматически.

#### Scenario: Старое уведомление
- **WHEN** уведомлению больше 90 дней
- **THEN** система удаляет его и не показывает в списке

### Requirement: Переход из уведомления

Переход по уведомлению SHALL открывать связанное устройство.

#### Scenario: Клик по уведомлению
- **WHEN** пользователь открывает уведомление об устройстве
- **THEN** система открывает карточку этого устройства

### Requirement: Список уведомлений

Список SHALL отдавать текущему пользователю только его уведомления, с
пагинацией и количеством непрочитанных.

#### Scenario: Список только свои
- **WHEN** пользователь запрашивает `GET /notifications`
- **THEN** в ответе только его уведомления и поля `items`, `total`, `page`,
  `page_size`, `unread`

#### Scenario: Пагинация
- **WHEN** пользователь запрашивает `GET /notifications?page=2&page_size=25`
- **THEN** в ответе вторая страница записей, а `total` и `unread` считаются по
  всем его уведомлениям

#### Scenario: Пустой список
- **WHEN** у пользователя нет уведомлений
- **THEN** система отвечает пустым `items` и `unread`, равным нулю

### Requirement: Недоступность чужого уведомления

Попытка отметить чужое или неизвестное уведомление SHALL заканчиваться
`404 NOT_FOUND` без раскрытия существования записи.

#### Scenario: Чужое уведомление
- **WHEN** пользователь отправляет `POST /notifications/{id}/read` на
  уведомление другого сотрудника
- **THEN** система отвечает 404 и уведомление остаётся непрочитанным

#### Scenario: Прочтение чужого списка
- **WHEN** пользователь вызывает `POST /notifications/read-all`
- **THEN** отмечаются только его собственные уведомления

### Requirement: Уведомление о деактивации сотрудника

При деактивации сотрудника система SHALL уведомить всех активных
администраторов, кроме инициатора.

#### Scenario: Деактивация сотрудника
- **WHEN** admin деактивирует сотрудника
- **THEN** каждый активный администратор, кроме инициатора, получает
  уведомление о деактивации

#### Scenario: Инициатор не дублирует уведомление
- **WHEN** администратор деактивирует сотрудника
- **THEN** сам инициатор уведомление не получает

### Requirement: Уведомление о смене роли

Система SHALL уведомлять сотрудника, когда admin меняет его роль.

#### Scenario: Роль изменена
- **WHEN** admin меняет роль сотрудника
- **THEN** сотрудник получает уведомление с новой ролью

#### Scenario: Роль не менялась
- **WHEN** admin правит карточку сотрудника без поля `role`
- **THEN** уведомление о смене роли не создаётся

### Requirement: Уведомление о сбросе пароля

Система SHALL уведомлять сотрудника, когда admin сбрасывает его пароль.

#### Scenario: Пароль сброшен
- **WHEN** admin устанавливает сотруднику новый пароль
- **THEN** сотрудник получает уведомление о сбросе

#### Scenario: Смена собственного пароля
- **WHEN** пользователь меняет пароль в своём профиле
- **THEN** уведомление о сбросе не создаётся
